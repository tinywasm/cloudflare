# D1 — Cloudflare D1 ORM Adapter

`github.com/tinywasm/cloudflare/d1` connects a Cloudflare D1 SQLite database to `tinywasm/orm` from within a Worker.

## Public API

```go
// NewEdge opens the named D1 binding (Cloudflare edge runtime) and returns an *orm.DB.
// WASM only — reads the binding from context.env.
// Returns ErrDatabaseNotFound if the binding is absent from the Worker env.
func NewEdge(bindingName string) (*orm.DB, error)

// NewEdgeSession opens the named D1 binding using the D1 Sessions API to route queries
// through read replicas when enabled. It uses store (per-request) to chain bookmarks.
func NewEdgeSession(bindingName string, store BookmarkStore) (*orm.DB, error)

var ErrDatabaseNotFound error

const (
    BookmarkFirstUnconstrained = "first-unconstrained"
    BookmarkFirstPrimary       = "first-primary"
)

type BookmarkStore interface {
    Bookmark() string
    SetBookmark(string)
}
```

`*orm.DB` exposes the standard tinywasm ORM methods: `Create`, `First`, `Save`, `Delete`, `CreateTable`, `DropTable`, `Close`.

For DDL migrations from **outside** a Worker (CI, a developer machine — where this binding does not exist), see `tinywasm/goflare`'s [docs/D1.md](https://github.com/tinywasm/goflare/blob/main/docs/D1.md) (`goflare.NewD1Migrator`). That is deliberately not in this package — see `AGENTS.md`, "no tooling code, ever, regardless of build tag".

## Read Replication and D1 Sessions API

Activating read replication on Cloudflare (`read_replication: auto`) **does not affect queries unless the D1 Sessions API is used**. Without `NewEdgeSession`, all queries continue to execute exclusively on the primary database instance.

To use read replication:

```go
//go:build wasm

package contact

import (
    "github.com/tinywasm/cloudflare/d1"
    "github.com/tinywasm/cloudflare/edge"
)

func handleRequest(ctx edge.Context) {
    store := edge.BookmarkStore(ctx)
    db, err := d1.NewEdgeSession("DB", store)
    if err != nil {
        // handle error
    }
    // use db...
}
```

`edge.BookmarkStore(ctx)` tracks bookmarks using `edge`'s request-scoped string storage (`ctx.SetValue`). Because state is per-request, concurrent requests inside the same isolate never mix database session bookmarks.

| Bookmark / Mode | Meaning |
|---|---|
| `"first-unconstrained"` | Initial query sent to any instance, including read replicas (fastest response). |
| `"first-primary"` | Initial query forced to primary instance (freshest data). |
| Chained Bookmark | Subsequent queries in the request pass the bookmark returned by previous queries, ensuring sequential consistency. |

## Usage

```go
//go:build wasm

package contact

import "github.com/tinywasm/cloudflare/d1"

func saveSubmission(form ContactForm) error {
    db, err := d1.NewEdge("DB") // "DB" matches the binding name in wrangler.toml
    if err != nil {
        return err
    }
    defer db.Close()

    if err := db.CreateTable(&Contact{}); err != nil {
        return err
    }
    return db.Create(&Contact{
        Nombre:  form.Nombre,
        Email:   form.Email,
        Mensaje: form.Mensaje,
    })
}
```

## Model setup

The source of truth is a `model.Definition` var. `ormc` reads it and generates the row struct plus the `Schema()`/`Pointers()`/`Validate()` methods `orm.DB` needs — see `tinywasm/model`'s [README](https://github.com/tinywasm/model/blob/main/README.md) for the full field-type reference.

```go
var ContactModel = model.Definition{
    Name: "contact",
    Fields: model.Fields{
        {Name: "id",      Type: model.Int(),  DB: &model.FieldDB{PK: true, AutoInc: true}},
        {Name: "nombre",  Type: model.Text(), NotNull: true},
        {Name: "email",   Type: model.Text(), NotNull: true},
        {Name: "mensaje", Type: model.Text()},
    },
}
```

```bash
ormc
```

generates:

```go
// Generated by ormc from ContactModel — do not edit.

type Contact struct {
    ID      int64
    Nombre  string
    Email   string
    Mensaje string
}

func (c *Contact) Schema() []model.Field { return ContactModel.Fields }
func (c *Contact) Pointers() []any       { return []any{&c.ID, &c.Nombre, &c.Email, &c.Mensaje} }
func (c *Contact) Validate(action byte) error { return model.ValidateFields(action, c) }
```

The binding name passed to `NewEdge` (`"DB"` above) is configured at deploy
time, not here — this repo is pure runtime and has no deploy-time
configuration. See `tinywasm/goflare`'s
[docs/D1.md](https://github.com/tinywasm/goflare/blob/main/docs/D1.md) for
how the binding is provisioned (`D1_DATABASE_ID`/`D1_DATABASE_NAME`; no
`wrangler.toml` — `goflare` talks to the Cloudflare API directly).

## Constraints

- `d1` only compiles for `GOOS=js GOARCH=wasm` — all files except `errors.go` carry `//go:build wasm`.
- No `database/sql`. D1 is accessed exclusively via the D1 JS API.
- No stdlib `fmt`, `errors`, `strings` — use `github.com/tinywasm/fmt`.

## Architecture

```
orm.DB
 └── d1.adapter        (orm.Executor, //go:build wasm)    — calls D1 JS API via AwaitPromise
 └── sqlt.Compiler     (orm.Compiler)                     — generates SQLite-dialect SQL
```

| Operation | D1 JS call (Direct) | D1 JS call (Session) |
|---|---|---|
| `Exec` | `db.prepare(sql).bind(...args).run()` | `db.withSession(bm).prepare(sql).bind(...args).run()` |
| `QueryRow` | `db.prepare(sql).bind(...args).raw({columnNames:true})` | `db.withSession(bm).prepare(sql).bind(...args).raw({columnNames:true})` |
| `Query` | `db.prepare(sql).bind(...args).raw({columnNames:true})` | `db.withSession(bm).prepare(sql).bind(...args).raw({columnNames:true})` |

The D1 binding is read from `js.Global().Get("context").Get("env").Get(bindingName)`.
